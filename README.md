# RRT Unit Portal — v4.5

## Что добавлено
- Полностью отключён Discord OAuth. Вход: Discord User ID + пароль. Первый вход: одноразовый код от Штаба.
- Сессионная cookie с серверным хранением сессии; пароль не хранится в браузере.
- Руководства по блокам: теория → короткая проверка только по этому блоку. Отдельного экзамена нет.
- ACE Medical: 10 блоков по исходной шпаргалке пользователя. В первом блоке есть вопрос «В какие дни/ивенты есть ACE Medical?» → «Пятница — TvT».
- Порядок движения: 7 простых блоков по предоставленному PDF, с оптимизированными схемами и lazy-loading.
- 3 неправильных ответа в блоке → возврат к теории и полный повтор блока. После второго возврата показывается «последняя попытка». После третьего провала блок блокируется. Сбросить попытки может только Штаб.
- История попыток и действий обучения хранится в D1.
- Исправлены критические несоответствия SQL INSERT в старой v4.
- Добавлены автоматические проверки в `tests/smoke.py`.

## Что НЕ сделано
- Нет итогового экзамена.
- Не добавлены выдуманные тактические правила сверх предоставленного PDF.
- Нет Discord OAuth.

## Перед публикацией
1. Применить `db/schema.sql` к D1.
2. Затем один раз применить `db/seed.sql` к D1 — он создаёт 9 блоков ACE Medical и 7 блоков порядка движения с вопросами.
3. В `worker/wrangler.toml заменить `REPLACE_WITH_D1_DATABASE_ID`.
4. Добавить secret `DISCORD_BOT_TOKEN` в Worker.
5. В `app.js` заменить `YOUR-RRT-API.workers.dev` на реальный URL Worker API.
6. Деплой Worker.
7. GitHub Pages публикует корень проекта.
8. Запустить `python tests/smoke.py`.

## Важно
Статические картинки движения маленькие и загружаются только при открытии соответствующего блока. Это снижает лишний трафик. Основная RRT GIF-эмблема остаётся единственным крупным статическим asset. Cloudflare кэширует статические assets.
